# Part 1. 화면 구조

## 1. 화면 목록

| ID | 화면 | 층 | 역할 |
|---|---|---|---|
| S-01 | 대시보드 (홈) | 공통 | 변화 요약 · 총자산 · 추이 · 목표 · 종목. 공식 일별 기록의 기준 날짜 · 시각을 표시하고, 수집되지 않은 금액이 있으면 "불완전"으로 표시(0으로 채우지 않음). 수동 새로고침 버튼은 두지 않음 |
| S-02 | **자산 기록** | 기반 | 날짜별 자산 기록 — **가계부 내역 화면** ★ |
| S-03 | **월간 결산** | 기반 | 한 달 결산, 지난 결산 넘겨보기 ★ |
| S-04 | 원인 분석 상세 | 핵심 ① | 급등락 원인 후보와 근거 ★ 체류 핵심 |
| S-05 | 종목 상세 | 핵심 ① | 종목 추이 · 손익 · 과거 이벤트 |
| S-06 | 목표 설정 · 진척 | 핵심 ② | 목표 등록, 진척 게이지, 시나리오 |
| S-07 | 예적금 비교 | 핵심 ③ | 보유 예적금과 공시 상품 비교 |
| S-08 | 알림 센터 | 공통 | 지난 알림 이력 |
| S-09 | 알림 설정 | 공통 | 트리거별 임계치 · 채널(웹 푸시 기본, 텔레그램 연결 · 해제) · 방해 금지 |
| S-10 | 계좌 연동 | 공통 | 기관 선택 · 인증(인증서 .der/.key 또는 ID/PW) · 연동 상태. 증권 연결 시 계좌번호(필수) · 계좌 비밀번호(선택) 입력. 연동 목록에 상태(ACTIVE · AUTH_FAILED · EXPIRED)와 재연결 동선 표시. 연결 직후 수집은 백그라운드라 첫 데이터가 늦게 보일 수 있음 — 계좌별 마지막 수집 시각으로 표시(수집 전이면 "수집 중"). **증권 수동 새로고침 버튼**과 진행 · 오류 · 쿨다운(남은 시간) 안내를 이 화면에 둔다(FR-CN-09). 기관 · 로그인 방식 미지원은 CODEF 오류 응답으로 안내하고, 시연 대상 기관에서 확인된 제한만 도움말에 적는다. 예적금 · 입출금 · 현금은 수기 자산으로 등록(입출금은 현금 유형) |
| S-11 | 온보딩 | 공통 | 가입(이메일 인증코드 단계 포함) → 연동 → 보유 종목 과거 이벤트 → 목표 → 알림. 로그인 화면에 비밀번호 재설정 동선 |

### 내비게이션
| 위치 | 메뉴 |
|---|---|
| 상단 / 하단 탭 | 홈 · **기록** · **결산** · 목표 · 알림 |
| 프로필 메뉴 | 계좌 연동 · 알림 설정 · 로그아웃 |

> **기록 · 결산을 주 메뉴에 둔다.** 가계부의 "내역 · 통계" 탭과 같은 자리다.

## 2. S-01 대시보드 (홈)

### 레이아웃 (상 → 하)

| 영역 | 구성 | 클릭 시 |
|---|---|---|
| ① 오늘의 변화 카드 (최대 3장) | 한 줄 요약 + 변동 금액 + 상태 색상 | → S-04 원인 분석 |
| ② 총자산 요약 | 총자산 · 전일 · 전월 · 전년 대비 (직전 COMPLETE 기록 기준), 시장가격 영향 · 기타 자산 변화 | 기간 탭 전환 |
| ③ 총자산 추이 차트 | 최근 12개월, 기간 탭(1M / 1Y / 전체) | 날짜 클릭 → S-02 해당 날짜 |
| ④ 목표 진척 게이지 | 진척률 · 도달 시점(수익률 0% 가정) · 최근 코멘트 | → S-06 |
| ⑤ 자산 구성 | 증권 · 예적금 · 현금 비중 | 자산군 클릭 → 목록 필터 |
| ⑥ 보유 종목 리스트 | 종목명 · 평가금액 · 손익률 · 당일 변동 | → S-05 |
| ⑦ 결산 배너 | **매월 1~7일에만 노출** — "9월 결산이 도착했어요" | → S-03 |
| ⑧ 예적금 배너 | 갈아탈 상품이 있을 때만 노출 | → S-07 |

### 변화 카드 선별 규칙
1. 당일 사용자 이벤트 중 **severity 높은 순**
2. 동일하면 **변동 금액 큰 순**
3. **상승 이벤트 최소 1장 보장** — 전부 하락이면 "가장 선방한 종목" 카드
4. 이벤트 없는 날은 **목표 진척 · 예적금 만기 · 결산** 카드로 채운다

> **매일 접속해도 볼 것이 있어야 한다.** 빈 화면은 이탈의 시작이다.

## 3. S-02 자산 기록 ★ 가계부 내역 화면

> 가계부의 "지출 내역" 화면에 대응한다. 기록 대상만 지출에서 **자산의 변화**로 바뀐다.

### 레이아웃

```
┌──────────────────────────────────────────┐
│  ◀  2026년 9월  ▶              [월 요약 ▾] │
│  이번 달  +1,240,000원  (+3.1%)            │
│  시장가격 +1,080,000 · 기타 +160,000        │
├──────────────────────────────────────────┤
│  9/19 (금)   41,380,000   +820,000  ▲ 🔔  │
│  9/18 (목)   40,560,000   -310,000  ▼     │
│  9/17 (수)   40,870,000   +120,000  ▲     │
│  9/16 (화)   40,750,000  -1,240,000 ▼ 🔔  │  ← 🔔 = 그날 이벤트 있음
│  9/15 (월)   41,990,000   +450,000  ▲     │
│  9/12 (금)   ⚠ 일부 계좌 수집 실패 · 비교 제외 │  ← PARTIAL
│  ...                                      │
└──────────────────────────────────────────┘
```

### 날짜 행을 펼치면
```
│  9/16 (화)   40,750,000  -1,240,000 ▼ 🔔  │
│  ├ 증권   28,400,000  -1,260,000          │
│  ├ 예적금 10,000,000       +2,000          │
│  ├ 현금    2,350,000      +18,000          │
│  └ 🔔 A종목 -7.2% · 공시 확인됨 [원인 보기] │
```

### 인터랙션
| 동작 | 반응 |
|---|---|
| 월 이동 ◀ ▶ | 해당 월 기록으로 전환 |
| 날짜 행 클릭 | 그날의 자산군 · 종목별 변동 펼침 |
| [원인 보기] | S-04 원인 분석 상세 |
| [월 요약 ▾] | 이번 달 누적 변화 · 상승일 / 하락일 수 표시 |
| 이번 달 요약 클릭 | 지난 달이면 S-03 결산으로 이동 |
| PARTIAL · FAILED 날짜 | 누락 표시, 전일 대비 · 하이라이트 제외. 다음 COMPLETE 날짜는 직전 COMPLETE 기록과 비교 — 표시 문구 · 마지막 확인 금액 노출 `[구현 시 확정]` |

> **입력 없이 매일 한 줄씩 쌓인다.** 가계부의 기록하는 느낌은 유지하되, 연동된 자산은 사용자가 매일 입력할 필요가 없다.
> 기록은 **계좌 연동일부터** 시작한다. 과거 날짜를 지어내 채우지 않는다.

## 4. S-03 월간 결산 ★

### 레이아웃

```
┌──────────────────────────────────────────┐
│  ◀ 8월     2026년 9월 결산     10월 ▶      │
├──────────────────────────────────────────┤
│  이번 달 자산  +1,240,000원  (+3.1%)       │
│  지난 달 대비  +480,000원 더 늘었어요        │
│  시장가격 영향 +1,080,000 · 기타 +160,000   │
│                                          │
│  "보유 종목 가격 상승폭이 컸던 한 달이에요.    │  ← LLM 한 줄 총평
│   16일에는 A종목이 공시와 같은 날 하락했어요"  │
├──────────────────────────────────────────┤
│  자산군별 증감                             │
│  증권 +1,180,000 ██████████████           │
│  예적금  +42,000 █                        │
│  현금    +18,000 ▏                        │
├──────────────────────────────────────────┤
│  이번 달 주요 이벤트                        │
│  9/16  A종목 -7.2%  공시     [원인 보기]    │
│  9/08  B종목 +6.1%  뉴스 4건  [원인 보기]    │
├──────────────────────────────────────────┤
│  가장 많이 오른 종목  B  +12.4%             │
│  가장 많이 내린 종목  A   -8.1%             │
├──────────────────────────────────────────┤
│  목표 진척   34% → 37%   (+3%p)           │
├──────────────────────────────────────────┤
│  10월 체크 포인트                           │
│  · 정기예금 10/24 만기 — 비교 상품 있음      │
│  · 목표 도달엔 월 45만원 필요               │
└──────────────────────────────────────────┘
```

### 인터랙션
| 동작 | 반응 |
|---|---|
| ◀ ▶ | 지난 · 다음 결산 넘겨보기 |
| 자산군 막대 클릭 | 해당 자산군의 종목별 증감 펼침 |
| [원인 보기] | S-04 |
| 종목명 클릭 | S-05 |
| 목표 진척 클릭 | S-06 |
| 체크 포인트 클릭 | S-07 또는 S-06 |

> **새 분석을 만들지 않고 모아 보여주는 화면**이다. 여기서 모든 핵심 기능으로 이동할 수 있어 **허브 역할**을 한다.
> 월초 · 월말은 해당 월의 첫 · 마지막 **COMPLETE 기록** 기준이다. 총평이 없어도 수치 결산만으로 완성된다.
> 기타 자산 변화의 원인은 추측하지 않는다 ("월급이 들어와서" 같은 문장 금지).

## 5. S-04 원인 분석 상세 ★ 체류 핵심

### 레이아웃

```
┌──────────────────────────────────────────┐
│ A종목 어제보다 -7.2%  (-124,000원)         │  ← 사용자별 계산
│ 내 자산의 34%  ·  원금 대비 -12%            │
├──────────────────────────────────────────┤
│ 근거 상태: 관련 근거 확인                   │  ← 공유 분석
│ "같은 날 실적 정정 공시가 있었습니다"         │
├──────────────────────────────────────────┤
│ 📄 공시  09:14  실적 정정 공시       [원문]  │
│ 📰 뉴스  10:32  실적 하향 조정 보도   [원문]  │  ← 근거 타임라인
│ 📰 뉴스  11:05  업종 전반 약세 보도   [원문]  │
├──────────────────────────────────────────┤
│ 시장 비교         [KOSPI ▾]                │
│ 내 종목 -7.2%  |  KOSPI -0.8%              │
│ → 시장보다 6.4%p 더 하락했습니다             │
├──────────────────────────────────────────┤
│ 이 종목의 지난 이벤트                        │
│ 08-14 +6.1%  ·  07-02 -5.5%               │
├──────────────────────────────────────────┤
│ [자산 기록에서 보기] [목표 영향] [알림 조정]  │
└──────────────────────────────────────────┘
```

### 인터랙션
| 동작 | 반응 |
|---|---|
| 근거 카드 | 원문 새 탭 |
| 시장 비교 토글 | KOSPI / KOSDAQ 전환 |
| 과거 이벤트 | 해당 날짜의 S-04 (순환) |
| 자산 기록에서 보기 | S-02 해당 날짜 펼침 상태 |
| 목표 영향 | S-06, 이벤트 전후 진척률 비교 |
| 알림 조정 | S-09 해당 트리거 |

### 근거 상태 표시 (v2.1: 확신도 4단계 대체)
| 상태 | 조건 | 표현 |
|---|---|---|
| 관련 근거 확인 | 필터를 통과한 공시 · 뉴스 1건 이상 | "같은 시점에 이런 공시 · 보도가 있었습니다" |
| 시장 · 업종 동반 움직임 | 근거 0건, 시장 대비 초과 변동이 작음 | "시장 전체가 함께 움직였습니다" |
| 관련 근거 확인 불가 | 근거 0건, 개별 움직임 | "관련 근거를 찾지 못했습니다" |

> 신뢰 등급이 아니라 **근거 확인 결과**다. 동반 판단 기준 · 공시 유형 필터 `[구현 시 확정]`
> 장 마감 이후 공개된 자료는 당일 변동의 근거처럼 표시하지 않는다 — 표시 방식(제외 / 별도 라벨) `[확인 필요]`
> ETF는 공시 · 뉴스 대신 시장 비교 중심으로 표시한다

### 요약이 없는 경우
| 상황 | 표시 |
|---|---|
| 근거 0건 | 템플릿 문구 + 시장 비교만 (LLM 미호출) |
| 한도 초과 · 예산 초과 · LLM 실패 | "요약을 준비하지 못했어요. 근거를 직접 확인해보세요" + 근거 타임라인 |

> 요약이 없어도 **근거 타임라인과 시장 비교는 항상 제공**한다.

## 6. S-06 목표 설정 · 진척

| 영역 | 구성 | 인터랙션 |
|---|---|---|
| 목표 요약 | 목표 금액 · 목표일 · 진척률 | — |
| 진척 게이지 | 현재 자산 / 목표 금액 | — |
| 진척 추이 | 일별 진척률 라인 차트 | 기간 전환 |
| 도달 시점 | 현재 자산 + 월 납입액, **수익률 0% 가정** 시뮬레이션 — 계산 기준 함께 표시 | — |
| 코멘트 | 목표 생성 · 변경 · 달성 · 기한 임박 · 월간 결산 시 갱신 — "현재 조건이면 목표일보다 약 7개월 늦어요" | — |
| **시나리오 슬라이더** | 월 납입액 조정 (수익률 시나리오는 향후 검토 `[구현 시 확정]`) | 드래그 시 **실시간 재계산** ★ |
| 예적금 연결 | 목표 시점 이내 만기 상품 | → S-07 |

> 시나리오 슬라이더는 **클라이언트에서 계산**한다. 서버 호출 · LLM 호출 없이 즉시 반응해야 만지고 싶어진다.

## 7. 전체 화면 전이도

```
                       [온보딩 S-11]
                             │
     가입 → 계좌 연동 → 보유 종목 30일 이벤트 → 목표 → 알림 설정
                             │
                             ▼
     ┌──────────────── [대시보드 S-01] ────────────────┐
     │          │           │            │           │
  변화 카드   추이 차트    목표 게이지    결산 배너   예적금 배너
     │          │           │            │           │
     ▼          ▼           ▼            ▼           ▼
 [원인분석]  [자산기록]    [목표]      [월간결산]   [예적금]
   S-04 ◀────▶ S-02         S-06  ◀────── S-03 ──────▶ S-07
     │                       ▲            │
     ├── 과거 이벤트 → S-04   │            ├── 이벤트 → S-04
     ├── 목표 영향 ──────────┘            └── 종목 → S-05
     └── 알림 조정 → S-09

 [알림 수신] ──클릭──▶ 유형별 딥링크 (아래 표)
```

# Part 2. 리텐션 설계

## 8. 문제 정의

> 가계부 · 자산 앱의 공통 실패 지점은 두 가지다.
> **① 입력이 귀찮아서 그만둔다 ② 볼 게 없어서 안 연다**

| 실패 원인 | 자산 가계부의 대응 |
|---|---|
| 입력이 귀찮다 | 자동 수집 · 자동 기록 — 연동된 자산은 매일 입력할 필요가 없다 |
| 볼 게 없다 | 알림으로 다시 부르고(재방문), 기록 · 원인 · 결산 · 목표로 붙잡는다(체류) |

---

## 9. 재방문 장치 — 알림은 문을 여는 열쇠

| 장치 | 주기 | 예시 | 성격 |
|---|---|---|---|
| 급등락 알림 | 이벤트 시 | "A종목 -7.2%, 같은 날 공시가 있었어요" | 이벤트성 |
| 장 마감 브리핑 | 평일 1회 | "오늘 자산 +82,000원. 상승 2 · 하락 1" | 일간 |
| 목표 진척 리포트 | 주 1회 | "이번 주 진척 34% → 37%" | 주간 |
| **월간 결산** | 매월 1일 | "9월 자산 +124만원, 결산이 도착했어요" | 월간 ★ |
| 예금 만기 | D-30 / D-7 | "만기 25일 전, 예상 수령액 5만원 차이" | 이벤트성 |

### 주기 설계
```
일간 ─ 장 마감 브리핑 ─────────────────── 최소 접점 보장
주간 ─ 목표 진척 리포트 ─────────────────── 목표 의식 유지
월간 ─ 월간 결산 ────────────────────────── 돌아보기 · 다음 달 계획
수시 ─ 급등락 · 만기 ───────────────────── 긴급도
```

> 이벤트성만 있으면 조용한 날엔 잊히고, 정기성만 있으면 무시하게 된다. **네 가지 주기를 섞는다.**

### 알림 피로도 관리
| 규칙 | 내용 |
|---|---|
| 일 평균 3건 이하 | NFR-US-01 |
| 급등락 개별 알림 일 3건 | 초과분은 **묶음 알림 1건** ("그 외 2종목이 크게 움직였어요") |
| 목표 코멘트 | 의미 있는 변화가 있을 때만 갱신, 진척 **알림은 주 1회**만 |
| 상승 소식도 보낸다 | 경고만 오는 앱은 열기 싫어진다 |
| 차단 대신 조정 | 알림 상세에 "이런 알림 그만 받기" / "기준 조정" |

## 10. 체류 장치 — 페이지는 머무는 이유

| 장치 | 화면 | 왜 머무는가 |
|---|---|---|
| **자산 기록 리스트** | S-02 | 가계부 내역처럼 스크롤하며 날짜를 펼쳐본다 |
| **지난 결산 넘겨보기** | S-03 | 월별 결산을 ◀ ▶로 비교한다 |
| **결산 허브** | S-03 | 결산에서 원인 · 종목 · 목표 · 예적금으로 이어진다 |
| **근거 타임라인** | S-04 | 뉴스 · 공시가 **읽을 거리** |
| **과거 이벤트 순환** | S-04 | 클릭하면 또 다른 원인 분석으로 이어진다 |
| **시나리오 슬라이더** | S-06 | 숫자를 바꿔보는 **만질 거리** |
| **기간 탭 · 시장 비교 토글** | S-01, S-04 | 맥락을 바꿔가며 본다 |
| **상승 하이라이트** | S-01 | 긍정 피드백 |

### 화면 간 순환 구조
```
      자산 기록 ◀──────▶ 원인 분석 ◀──────▶ 과거 이벤트
          ▲                  │
          │                  ▼
      월간 결산 ─────────▶ 목표 ─────────▶ 예적금
```
> 어느 화면에서 들어와도 **다음으로 갈 곳이 있다.** 막다른 화면이 없도록 설계한다.

### 체류 시간 목표
| 화면 | 목표 | 근거 |
|---|---|---|
| S-01 대시보드 | 30초+ | 요약 확인 + 카드 1회 클릭 |
| S-02 자산 기록 | 45초+ | 날짜 2회 이상 펼침 |
| S-03 월간 결산 | 90초+ | 섹션 스크롤 + 1회 이상 이동 |
| S-04 원인 분석 | 90초+ | 근거 2건 이상 확인 |
| S-06 목표 | 60초+ | 슬라이더 1회 이상 조작 |

> 프론트엔드 이벤트 로깅으로 측정하고 결과 보고서의 정량 지표로 사용한다.

## 11. 온보딩 — 첫날부터 볼 것이 있게

| 단계 | 화면 | 핵심 |
|---|---|---|
| 1 | 가입 | 이메일 인증코드 확인 → 이메일 · 비밀번호 · 약관 동의 |
| 2 | 계좌 연동 | 증권 우선, 예적금 선택 (예적금은 수기 입력) |
| 3 | **보유 종목 30일 즉시 분석** | 연동 직후 보유 종목의 최근 30일 시세를 소급해 **종목 추이와 ±5% 이벤트를 바로** 보여준다 (과거 총자산 기록은 만들지 않음) |
| 4 | 목표 입력 | 건너뛰기 가능, 이후 대시보드 배너로 재유도 |
| 5 | 알림 설정 | 기본값 적용 후 조정 안내 + 웹 푸시 권한 요청 (텔레그램 연결은 선택, 건너뛰기 가능) |

> 3단계가 핵심이다. 자산 기록은 연동일부터 한 줄씩 쌓이지만, **보유 종목의 30일 추이와 과거 이벤트**로 첫날부터 볼 것을 만든다.
> 빈 화면을 사실이 아닌 과거 자산 기록으로 채우지 않는다 — 현재 수량 × 과거 시세는 실제 자산이 아니다.

## 12. 이탈 방지

| 상황 | 대응 |
|---|---|
| 알림이 많다고 느낄 때 | "이런 알림 그만 받기" → 차단 대신 조정 |
| 이벤트 없는 날 | 목표 진척 · 만기 · 결산 카드로 대시보드 채움 |
| 초기 30일 | 전월 대비 대신 연동 이후 누적 변화 + 보유 종목 과거 이벤트 |
| 수집 일부 실패 | 그날 기록은 누락 표시, 다음 COMPLETE 기록부터 비교 재개 |
| 초기 1년 | 전년 대비 대신 연동 이후 누적 변화 |
| 인증 만료 | 재인증 알림, 미해결 시 대시보드 상단 배너 유지 |
| 요약이 없을 때 | 근거 타임라인 · 시장 비교는 항상 제공 |

## 13. 발표용 요약

> **"왜 쓰는가"는 알림이 답하고, "왜 계속 쓰는가"는 페이지가 답한다.**

1. **입력 없는 가계부** — 가계부 이탈의 1순위 원인을 자동 기록으로 제거
2. **네 가지 주기의 알림** — 수시 · 일간 · 주간 · 월간이 조용한 날에도 접점을 만든다
3. **월간 결산이 허브** — 결산 하나에서 모든 기능으로 이어진다
4. **막다른 화면이 없다** — 기록 · 원인 · 결산 · 목표가 서로 순환
5. **첫날부터 볼 것이 있다** — 보유 종목 30일 이력을 소급하되, 과거 자산은 지어내지 않는다
