# 한투(KIS) Open API 실호출 검증 기록

> 관련: 01 §14 #5 · #23 · #24, 04 FR-MK-01 · FR-MK-06, 05 §4.6 · §4.9
> 6주차 Step 0에서 "확인 불가 · 추정"으로 남긴 항목을 실제 응답으로 확인한 기록이다. 결과를 보고 Step 2 이후 결정을 확정한다.
> 설계 문서(01~05)는 여기서 고치지 않는다. 확정되면 "문서 반영 필요"로 따로 올린다.

## 실행 방법

실전 앱키 · 시크릿이 필요하다. 실행할 때마다 토큰 발급 1회(알림톡 1건)가 생긴다(6시간 안이면 같은 토큰).
결과는 `backend/build/kis-live/verification-<시각>.md`에 남는다 — 아래 표로 옮겨 적는다. `gradlew clean`을 하면 지워진다.

PowerShell:
```powershell
$env:KIS_APP_KEY = '<앱키>'; $env:KIS_APP_SECRET = '<시크릿>'; cd backend; .\gradlew.bat kisLiveTest
```

- 거래정지 종목을 함께 보려면 `$env:KIS_HALTED_TICKER = '<종목코드>'`를 추가한다(V3).
- 모의 도메인으로 실행하려면 `$env:KIS_BASE_URL = 'https://openapivts.koreainvestment.com:29443'`를 추가한다. 종목정보 API는 모의에서 지원하지 않을 수 있다.
- 기본 `./gradlew test`에서는 실행되지 않는다(`@Tag("kis-live")` 제외).

| # | 언제 실행 | 무엇을 보나 |
|---|---|---|
| V1 · V2 · V3 | 아무 때나 1회 | 변동률 기준, ETF · 거래정지 필드 |
| V4 | 거래일 16:00 이후 1회 + 다음 날 1회 | 같은 거래일 행의 종가 · 대비율이 같은지 |
| V5 | 주말 · 공휴일 1회 | 최신 행이 직전 거래일인지 |

## 결과

### V1 — `prdy_ctrt` 기준 (#5)

`inquire-daily-itemchartprice`의 일별 행(output2)에는 `prdy_ctrt`가 없다(공식 예제 필드 기준). 그래서 두 가지를 함께 본다.
1. 최근 30거래일: `prdy_ctrt ≈ prdy_vrss ÷ (종가 − prdy_vrss) × 100` — 대비율이 대비(원)와 같은 기준으로 계산되는지
2. 액면분할일(005930, 2018-05-04, 50:1, 원주가 조회): `prdy_vrss`가 `종가 − 직전 종가`와 같은지

| 항목 | 값 |
|---|---|
| 실행 | 2026-10-13 13:24 (실전 도메인) |
| 최근 30일 일치 일수 | 30 / 30 — `prdy_ctrt`는 `prdy_vrss`와 같은 기준으로 계산됨 |
| 2018-05-04 종가 | 51,900 |
| 2018-05-04 prdy_vrss | −1,100 (부호 5 = 하락) |
| 종가 − 직전 행 종가 | −2,598,100 (직전 2018-05-03 종가 2,650,000) |
| 결론 | **기준가(분할 조정) 대비.** −1,100 = 51,900 − 53,000(= 2,650,000 ÷ 50). 액면분할일에도 `prdy_ctrt`는 약 −2.08%로 나온다 → 01 §14 #5 전제("한투 변동률을 그대로 쓴다") 성립 |

- 분할일 행의 `flng_cls_code`는 `00`, `prtt_rate`는 `0.00`, `mod_yn`은 `N`이었다(원주가 조회). 이 필드들로 분할일을 구분할 수는 없다.
- `stock_prices.prev_close_price`를 "직전 행 종가"로 저장하면 분할일에는 `change_rate ≠ 종가 ÷ 전일 종가 − 1`이 된다(05 §4.9 정의 보강 필요).

### V2 — ETF 판별 필드 (#24)

| 종목 | scty_grp_id_cd | etf_dvsn_cd | etf_type_cd |
|---|---|---|---|
| 069500 (ETF, KODEX 200) | `EF` | `02` | `01` |
| 005930 (주식, 삼성전자) | `ST` | `0` | (빈 값) |

결론: **`scty_grp_id_cd`로 판별한다 — `EF` = ETF, `ST` = 주식.** `etf_dvsn_cd`는 주식에서도 `0`이 와서 빈 값/0 구분이 필요하므로 보조로만 쓴다. ETN(`EN`으로 추정) 등 다른 그룹 코드는 아직 확인하지 않았다.

| 종목 | tr_stop_yn | admn_item_yn | 비고 |
|---|---|---|---|
| 069500 | `N` | `N` | |
| 005930 | `N` | `N` | |
| (거래정지 종목) | 미실행 | | `KIS_HALTED_TICKER` 지정 필요 |

결론: 후보 필드는 `tr_stop_yn`(거래정지여부)이다. 정상 종목에서 `N`인 것까지 확인했고, **거래정지 종목에서 `Y`가 오는지는 아직 확인하지 못했다.**

### V4 — 16:00 종가 확정

| 실행 시각 | 거래일 | 종가 | 대비율 |
|---|---|---|---|
| 2026-10-13 13:24 (장중 · 참고) | 2026-10-13 | 231,000 | −7.78% |
| 2026-10-28 04:56 (다음 날 · 장 시작 전) | 2026-10-27 | 225,000 | +5.63% |

- 2026-10-28 04:56 실행은 10/27 행의 "다음 날" 값이다. 16:00 직후 조회는 하지 않았다.

- 장중(13:24)에도 오늘 날짜 행이 이미 있고, 종가 칸에 **현재가**가 들어온다. → 휴장일 판정("최신 거래일 = 오늘")은 장중에도 성립하지만, 종가로 쓰려면 장 마감(15:30) 이후 조회가 필요하다.

결론: **간접 확인으로 종료.** 정규장 종가는 15:30 종가 단일가로 정해지고 시간외 거래가 바꾸지 않으므로 16:00 조회값을 최종값으로 본다. 16:00 값과 다음 날 값의 직접 비교는 따로 실행하지 않고, 일일 배치 운영 뒤 `stock_prices`에 저장된 16:00 종가를 다음 날 조회값과 비교하는 것으로 대신한다. 다르면 16:00 실행 시각을 재검토한다.
