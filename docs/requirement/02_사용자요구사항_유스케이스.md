## 2. 사용자 정의

### 2.1 주 사용자 (Primary Persona)

**"증권 계좌는 있는데, 잔고 숫자만 보고 있는 사람"**

| 항목 | 내용 |
|---|---|
| 상황 | 증권 계좌와 예적금을 보유. 매일 앱을 열어 잔고를 확인하지만 숫자만 본다 |
| 행동 | 자산이 크게 떨어지면 검색창에 종목명을 쳐서 뉴스를 찾아본다 |
| 경험 | 가계부를 써본 적은 있지만 매번 입력하는 게 귀찮아 그만뒀다 |
| 불편 | 이번 달 자산이 얼마나 늘었는지, 왜 그런지 한눈에 정리된 걸 본 적이 없다 |
| 불편 | 왜 움직였는지 알려면 매번 직접 찾아야 하고, 어떤 뉴스가 관련 있는지 판단이 어렵다 |
| 불편 | 모으고는 있는데 목표까지 얼마나 왔는지, 이 속도가 맞는지 알 수 없다 |
| 불편 | 예금 만기를 놓쳐 자동 재예치로 낮은 금리에 묶인 경험이 있다 |
| 기대 | **입력하지 않아도 자산 변화가 기록되고, 왜 변했는지까지 정리되면 좋겠다** |

### 2.2 액터
| 액터 | 역할 |
|---|---|
| 사용자 | 증권 · 예적금 자산을 보유한 개인 |
| 시스템 배치 | 자동 수집 · 기록 · 감지 · 분석 · 결산 · 발송 주체 |
| 관리자 | 운영 지표 확인 (Grafana, 제품 화면 외부) |
| 외부 기관 | CODEF, 한국투자증권, DART, 뉴스 제공처(후보: 네이버), 한국은행, 금융감독원, OpenAI |

## 5. 유스케이스 명세

### UC-01. 계좌 연동

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **목적** | 증권 계좌를 서비스에 연결한다 (예적금 · 입출금 계좌는 수기 입력 — CODEF 은행 수집은 이후 개발) |
| **선행조건** | 회원가입 완료, 해당 기관 계정 보유 |
| **트리거** | 최초 온보딩 또는 계좌 추가 |

**주 흐름**
1. 사용자가 기관을 선택한다
2. 인증 정보(인증서 또는 ID/PW)와 증권 계좌번호(필수) · 계좌 비밀번호(선택)를 입력한다
3. 시스템이 CODEF로 커넥티드 아이디를 발급받는다
4. 인증 정보를 AES-256으로 암호화해 저장한다
5. 연동 저장이 끝나면 백그라운드에서 계좌 · 보유 종목 정보를 최초 수집하고 **연동일의 첫 자산 기록**을 생성한다 — 사용자 자산 기록은 이날부터 시작한다
6. 보유 종목의 **최근 30일 시세**를 소급 수집한다
7. 최근 30일 중 ±5% 이상 움직인 날을 찾아 **보유 종목의 과거 이벤트**(연동 전 이벤트)를 생성한다 — 과거 총자산 · 내 손익 · 비중은 만들지 않는다
8. 대시보드로 이동해 **첫 접속부터 볼 것이 있는 상태**로 시작한다 (보유 종목 30일 추이 · 과거 이벤트)

**대안 흐름**
- 3a. 인증 실패 → 오류 유형별 안내 (비밀번호 오류 / 기관 점검 / 인증서 만료)
- 3b. 이미 연결했던 기관(인증 실패 · 만료 · 해지 상태) → 같은 연동을 새 인증 정보로 갱신해 정상 상태로 복구
- 5a. 수집 시간 초과 → 진행 상태를 표시하고 백그라운드 처리 후 완료 알림
- 5b. 일부 기관 실패 → 성공한 기관 정보는 반영하되 첫 자산 기록은 **PARTIAL**로 저장하고, 실패 기관은 재시도 안내
- 5c. 최초 수집이 실패해도 연동은 유지된다
- 7a. 과거 이벤트가 없음 → "보유 종목은 최근 30일간 큰 변동이 없었습니다"로 표시

**사후조건** 커넥티드 아이디 저장, 연동일 첫 스냅샷 생성, 보유 종목 과거 이벤트 생성 (과거 날짜 자산 스냅샷은 생성하지 않음)

### UC-02. 자산 기록 · 추이 확인

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **목적** | 가계부처럼 쌓인 자산 기록과 변화 추이를 확인한다 |
| **선행조건** | 자산 연동 완료, 스냅샷 1일 이상 |
| **트리거** | 대시보드 또는 자산 기록 화면 진입 |

**주 흐름**
1. 사용자가 대시보드에 진입한다
2. 시스템이 총자산과 전일 · 전월 · 전년 대비 증감을 표시한다 — 비교 기준은 **직전 COMPLETE 기록**이며, 증감은 **시장가격 영향 · 기타 자산 변화**로 구분한다
3. 최근 12개월 총자산 추이 차트와 자산 구성 비중을 표시한다
4. 사용자가 '자산 기록'을 누른다
5. 날짜별 자산 기록이 **가계부 내역처럼** 월 단위로 나열된다 (날짜 · 총자산 · 전일 대비 · 이벤트 아이콘)
6. 사용자가 특정 날짜를 누른다
7. 그날의 자산 구성과 종목별 변동, 발생한 이벤트가 펼쳐진다
8. 이벤트가 있으면 원인 분석 상세로 이동할 수 있다

**대안 흐름**
- 2a. 스냅샷 30일 미만 → 전월 대비를 숨기고 "데이터 축적 중" 표시
- 2b. 스냅샷 1년 미만 → 전년 대비를 숨기고 연동 이후 누적 변화로 대체
- 2c. 자산이 증가한 날 → 상승 하이라이트 카드를 상단에 노출 (시장가격 영향 · 기타 자산 변화 구분, 기타 변화의 원인은 추측하지 않음)
- 2d. 해당 날짜 기록이 PARTIAL · FAILED → 비교 · 하이라이트에서 제외하고 누락 표시 (표시 방식 `[구현 시 확정]`)
- 5a. 휴장일 → 기록을 생략하고 직전 거래일에 묶어 표시

### UC-03. 월간 결산 확인

| 항목 | 내용 |
|---|---|
| **액터** | 시스템 배치 (주), 사용자 (부) |
| **목적** | 한 달간의 자산 변화를 가계부 결산처럼 돌아본다 |
| **선행조건** | 해당 월 스냅샷 1일 이상 |
| **트리거** | 매월 1일 배치 |

**주 흐름**
1. 배치가 지난 달의 첫 · 마지막 **COMPLETE** 스냅샷을 조회한다
2. 총자산 증감액 · 증감률과 전월 대비 변화, **시장가격 영향 · 기타 자산 변화**를 계산한다
3. 증권 · 예적금 · 현금의 **자산군별 증감액**을 계산한다
4. 지난 달 급등락 이벤트 상위 3건과 원인 요약을 가져온다 (UC-04 결과 재사용)
5. 종목별 월간 손익 순위를 산출한다
6. 목표가 있으면 월초 대비 진척 변화를 가져온다 (UC-05 결과 재사용)
7. 다음 달 만기 예정 예적금과 목표 필요 납입액을 체크 포인트로 정리한다
8. LLM이 한 줄 총평을 생성한다
9. 결산을 저장하고 웹 푸시(요약)로 발송한다. 텔레그램을 연결한 사용자에게는 결산 전문을 함께 보낸다
10. 사용자가 알림을 눌러 결산 화면을 연다
11. 사용자가 이전 달 버튼으로 지난 결산을 넘겨본다

**대안 흐름**
- 1a. 월 중 가입해 데이터가 일부만 있음 → 가입일 기준으로 계산하고 "N일간의 결산"으로 표시
- 1b. 해당 월 COMPLETE 기록이 없음 → 수치 결산을 만들지 않고 기록 부족을 안내
- 4a. 지난 달 이벤트 없음 → "큰 변동 없이 안정적인 한 달이었습니다"
- 6a. 목표 미등록 → 목표 항목 대신 "목표를 설정해보세요" 안내
- 8a. LLM 실패 · 한도 초과 → 총평 없이 수치 결산만 발송

**사후조건** 월간 결산이 저장되어 이후 넘겨보기에 사용된다

### UC-04. 종목 급등락 원인 확인 ★ 핵심

| 항목 | 내용 |
|---|---|
| **액터** | 시스템 배치 (주), 사용자 (부) |
| **목적** | 보유 종목의 급격한 변동 원인을 파악한다 |
| **선행조건** | 증권 계좌 연동, 보유 종목 1개 이상 |
| **트리거** | 보유 종목의 **전 거래일 대비 당일 가격 변동률**이 임계치(기본 ±5%) 이상 |

**주 흐름**
1. 배치가 장 마감 후 보유 종목 시세를 수집한다
2. 사용자별 임계치(기본값 또는 사용자 설정값)로 변동 종목을 찾는다 — **상승 · 하락 모두**
3. 해당 종목 · 날짜의 **공유 분석**이 이미 있는지 확인한다
4. 없으면 분산 락을 잡고 공유 분석을 생성한다
   - 4-1. DART 공시, 뉴스, 지수 · 거시지표를 수집한다 — 근거의 발표 · 게시 시각을 함께 기록하고, 행정성 · 정기성 공시는 제외한다
   - 4-2. 지수 대비 초과 변동을 계산한다
   - 4-3. **근거 상태**(관련 근거 확인 / 시장 · 업종 동반 움직임 / 관련 근거 확인 불가)를 판정하고, 근거가 있으면 LLM이 요약한다 — 장 마감 이후 공개된 자료는 당일 변동의 원인처럼 표현하지 않는다
5. 사용자별 이벤트를 생성해 공유 분석과 연결한다 (내 비중 · 내 손익은 사용자별로 계산)
6. 알림을 생성해 발송한다
7. 사용자가 알림을 누른다
8. 원인 분석 상세에서 변동 요약 · 근거 상태 · 근거 타임라인 · 시장 비교를 확인한다
9. 사용자가 근거 카드를 눌러 원문을 확인한다

**대안 흐름**
- 2a. ETF → 공시 · 뉴스를 수집하지 않고 지수 · 시장 비교 중심으로 분석
- 3a. 공유 분석이 이미 있음 → **LLM 호출 없이** 재사용 (다른 사용자가 먼저 생성)
- 4a. 다른 요청이 락을 보유 중 → 대기 후 완성된 분석을 재사용
- 4-3a. 근거 0건 → LLM 호출 없이 "관련 근거를 찾지 못했습니다. 시장 전체가 N% 움직였습니다", 근거 상태는 시장 비교에 따라 '시장 · 업종 동반 움직임' 또는 '관련 근거 확인 불가'
- 4-3b. LLM 실패 → 근거 목록만 제공, 재시도 큐 적재
- 4-3c. 사용자 일일 신규 요약 한도(10건) 초과 → 변동률 큰 순으로 요약, 나머지는 근거 목록만
- 4-3d. 전역 예산 초과 → 요약 생략 모드 (근거 목록은 계속 제공)
- 6a. 하루 개별 알림 3건 초과 → 나머지는 **묶음 알림 1건**으로 발송 ("그 외 2종목이 크게 움직였어요")
- 7a. 알림을 무시 → 다음 접속 시 대시보드 변화 카드로 노출

**사후조건** 공유 분석 · 근거 · 사용자 이벤트가 저장되어 자산 기록과 월간 결산에 사용된다

### UC-05. 투자 목표 설정 및 진척 확인

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **목적** | 목표를 등록하고 달성 가능성을 판단한다 |
| **선행조건** | 자산 연동 완료 |
| **트리거** | 목표 화면 진입 |

**주 흐름**
1. 사용자가 목표 금액 · 목표 시점 · 월 납입 가능액을 입력한다
2. 시스템이 현재 자산 기준 진척률을 계산한다
3. 현재 자산 + 월 납입 가능액, **수익률 0%** 기준으로 도달 시점을 시뮬레이션한다 (예측이 아닌 계산 결과)
4. 목표 시점과 시뮬레이션 결과의 차이를 보여주고, 목표 등록 시점의 코멘트를 제시한다
5. 사용자가 시나리오 슬라이더로 월 납입액을 조정한다
6. 도달 예상 시점이 실시간으로 갱신된다 (클라이언트 계산)
7. 사용자가 목표를 저장한다
8. 이후 매일 진척이 기록되고(COMPLETE 기록 기준), 코멘트는 목표 변경 · 달성 · 기한 임박 · 월간 결산 등 **의미 있는 변화가 있을 때만** 갱신된다
9. 대시보드에 진척 게이지가 상시 노출되고, 주 1회 진척 리포트 알림을 받는다

**대안 흐름**
- 3a. 시뮬레이션 결과가 목표 시점을 넘김 → 목표 시점에 맞추기 위한 필요 월 납입액 제시 (계산 기준: (목표 금액 − 현재 자산) ÷ 남은 개월 수, 수익률 0%)
- 3b. 월 납입 가능액 0원 → 도달 시점 대신 필요 월 납입액만 제시
- 4a. 목표 시점 도달 가능 → 긍정 코멘트와 여유분 표시
- 7a. 목표가 이미 존재 → 기존 목표 수정 또는 추가 후 대표 목표 선택
- 8a. 목표 금액 도달 → 달성 알림 발송, 상태를 '달성'으로 변경

### UC-06. 예금 만기 갈아타기

| 항목 | 내용 |
|---|---|
| **액터** | 시스템 배치 (주), 사용자 (부) |
| **목적** | 만기 전에 비교 가능한 정기예금 상품의 예상 수령액을 확인한다 |
| **선행조건** | 예적금 연동, 만기일 보유 |
| **트리거** | 만기 D-30 / D-7 또는 사용자 지정 시점 |

**주 흐름**
1. 배치가 만기 도래 예정 예적금을 조회한다
2. 금감원 공시의 **정기예금** 상품 중 동일 조건(기간 · 금액) 상품을 매칭한다
3. 등록된 목표가 있으면 **목표 시점 이내 만기 상품을 우선 정렬**한다
4. **예상 수령액 차이**를 금액으로 계산하고 계산 기준(원금 · 기간 · 적용 금리)을 함께 표시한다
5. 알림을 생성해 발송한다
6. 사용자가 알림을 눌러 비교 화면으로 이동한다
7. 상품 목록과 예상 수령액 차이를 확인한다
8. 상품을 선택하면 해당 기관 정보를 안내한다

**대안 흐름**
- 1a. 적금 만기 → 만기 알림만 제공 (적금 상품 비교 포함 여부 `[구현 시 확정]`)
- 2a. 더 나은 상품 없음 → "현재 비교 가능한 상품 중 입력한 조건에서 더 높은 예상 수령액의 상품을 찾지 못했습니다" (비교 범위를 밝힌 긍정 확인)
- 3a. 목표 없음 → 금리 순으로만 정렬
- 4a. 자동 재예치 설정 → 재예치 시 예상 손해액 함께 표시
- 8a. 가입 · 이체는 제공하지 않음 → 기관 안내까지만

### UC-07. 알림 임계치 설정

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **목적** | 알림 빈도와 민감도를 내 기준에 맞춘다 |
| **선행조건** | 회원가입 완료 |
| **트리거** | 온보딩 또는 알림 화면의 '설정 조정' |

**주 흐름**
1. 사용자가 알림 설정 화면에 진입한다
2. 시스템이 트리거 목록과 현재 적용값(기본값 / 사용자값)을 표시한다
3. 사용자가 종목 변동 임계치를 조정한다 (예: 5% → 8%)
4. 시스템이 허용 범위를 검증한다
5. 사용자가 수신 채널(웹 푸시 기본 · 텔레그램 연결은 선택)과 방해 금지 시간대를 설정한다
6. 저장하면 다음 감지 주기부터 적용된다

**대안 흐름**
- 3a. 허용 범위 밖 → 경고와 함께 입력 거부
- 3b. 알림에서 '이런 알림 그만 받기' → 해당 트리거 비활성화
- 3c. '기본값으로 되돌리기' → 사용자 설정 삭제, 기본값 적용
- 6a. 저장 실패 → 기존 값 유지, 오류 안내
