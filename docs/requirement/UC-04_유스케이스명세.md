## 2. 주 성공 시나리오

1. 시스템 타이머가 영업일 장 마감 후 급등락 점검을 개시한다.
2. 시스템은 한국투자증권에서 사용자 보유 종목의 당일 시세를 조회하고, 사용자 임계치(기본 ±5%) 이상 움직인 종목을 상승 · 하락 구분 없이 감지한다. [FR-DT-02, FR-DT-03]
3. 시스템은 DART · 네이버 뉴스 · 한국은행 ECOS에서 해당 종목 · 날짜의 공시 · 기사 · 지표를 근거로 수집한다. [FR-CA-01, FR-CA-02]
4. 시스템은 같은 날 지수 변동률과 비교해 시장 대비 초과 변동을 계산하고, 근거 상태(관련 근거 확인 / 시장 · 업종 동반 움직임 / 관련 근거 확인 불가)를 판정한다. 신뢰 등급은 매기지 않는다. [FR-CA-05, FR-CA-06]
5. 시스템은 수집한 근거를 OpenAI에 전달하고, "같은 시점에 ~가 있었다" 형식의 원인 후보 요약을 받는다. [FR-CA-03, FR-CA-08, FR-CA-09]
6. 시스템은 사용자의 변동 금액 · 비중 · 손익을 결합한 이벤트를 기록하고, 사용자에게 급등락 알림을 보낸다. 웹 푸시로는 요약 + 원인 분석 화면 딥링크를, 텔레그램을 연결한 사용자에게는 원인 후보 요약 · 근거 링크를 포함한 전문을 보낸다. [FR-CA-12, FR-NT-02, FR-NT-04]
7. 사용자는 알림에서 해당 종목의 원인 확인을 요청한다.
8. 시스템은 변동 요약(변동률과 금액), 근거 상태, 원인 후보 요약, 근거 타임라인, 시장 비교를 제시한다. [FR-CA-04, FR-NT-10 · S-04]
9. 사용자는 근거 하나를 골라 원문 확인을 요청한다.
10. 시스템은 해당 공시 · 기사의 원문을 제시한다.

## 3. 확장 (대체 흐름)

**2a. 임계치 이상 움직인 보유 종목이 없는 경우:**
  2a1. 시스템은 이벤트와 알림을 만들지 않는다.
  2a2. 유스케이스를 종료한다.

**2b. 한국투자증권 시세 조회가 실패한 경우:**
  2b1. 시스템은 재시도한다. [NFR-PF-05]
  2b2. 재시도가 모두 실패하면 해당 일 점검을 실패로 기록하고 유스케이스를 종료한다. 실패한 점검은 다시 실행할 수 있다. [NFR-RL-03]

**2c. 같은 종목 · 날짜에 대해 이미 감지된 이벤트가 있는 경우:**
  2c1. 시스템은 중복 감지를 만들지 않고 해당 종목의 처리를 종료한다. [FR-DT-06]

**3a. 같은 종목 · 날짜의 분석이 이미 존재하는 경우 (다른 사용자 보유분으로 먼저 생성됨):**
  3a1. 시스템은 기존 분석과 근거를 재사용한다. 요약 생성 한도는 차감하지 않는다. [FR-CA-10, FR-AI-03]
  3a2. 6단계로 진행한다.

**3b. 일부 정보원(DART · 네이버 · ECOS) 수집이 실패한 경우:**
  3b1. 시스템은 수집에 성공한 근거만으로 4단계를 진행한다. [NFR-RL-04]

**3c. 수집된 근거가 0건인 경우:**
  3c1. 시스템은 시장 대비 초과 변동이 기준 이내면 '시장 · 업종 동반 움직임', 기준을 넘으면 '관련 근거 확인 불가'로 판정한다. 초과 변동 기준은 `[구현 시 확정]`. [FR-CA-06]
  3c2. 시스템은 OpenAI를 호출하지 않고 "특별한 뉴스를 찾지 못했습니다. 같은 날 시장 전체는 N% 움직였습니다" 문구를 사용한다. [FR-CA-07, FR-AI-07]
  3c3. 6단계로 진행한다.

**5a. 사용자의 당일 신규 요약이 10건을 넘은 경우:**
  5a1. 시스템은 변동률이 큰 종목부터 10건까지만 요약을 받는다.
  5a2. 나머지 종목은 요약 없이 6단계로 진행한다. [FR-AI-02, FR-AI-04]

**5b. 서비스 전체 LLM 예산을 초과한 경우:**
  5b1. 시스템은 요약을 생략하고 6단계로 진행한다. [FR-AI-08]

**5c. OpenAI 호출이 실패한 경우:**
  5c1. 시스템은 해당 분석을 재시도 대상으로 기록한다. [FR-CA-14]
  5c2. 요약 없이 6단계로 진행한다.

**6a. 사용자가 급등락 알림 수신을 꺼 둔 경우:**
  6a1. 시스템은 이벤트만 기록하고 알림을 보내지 않는다. [FR-DT-02]
  6a2. 7a로 진행한다.

**6b. 사용자의 당일 개별 급등락 알림이 3건을 넘는 경우:**
  6b1. 시스템은 초과분을 묶음 알림 1건으로 보낸다 ("그 외 2종목이 크게 움직였어요"). [FR-NT-12]

**6c. 알림 발송이 실패한 경우:**
  6c1. 시스템은 간격을 늘려가며 최대 3회 재발송한다.
  6c2. 모두 실패하면 발송 실패로 기록하고 7a로 진행한다. [FR-NT-06]
  6c3. 재발송과 실패 기록은 채널별로 한다 — 웹 푸시가 실패해도 텔레그램 발송은 그대로 진행한다. [FR-NT-07]

**6d. 사용자가 텔레그램을 연결하지 않은 경우:**
  6d1. 시스템은 웹 푸시로만 보낸다. [FR-NT-04]

**7a. 사용자가 알림에 응답하지 않은 경우:**
  7a1. 사용자가 다음에 서비스에 접속하면 시스템은 대시보드의 오늘의 변화 영역에 해당 이벤트를 제시한다. [S-01]
  7a2. 사용자가 해당 이벤트의 원인 확인을 요청하면 8단계로 진행한다.

**8a. 요약이 없는 경우 (5a · 5b · 5c):**
  8a1. 시스템은 "요약을 준비하지 못했어요. 근거를 직접 확인해보세요"를 안내하고, 근거 타임라인과 시장 비교는 그대로 제시한다. [NFR-RL-05]

**8b. 사용자가 비교 지수 변경을 요청한 경우:**
  8b1. 시스템은 선택한 지수(KOSPI / KOSDAQ) 기준으로 시장 비교를 다시 제시한다.

## 4. 특별 요구사항

- 장 마감 점검 시작부터 알림 도달까지 30분 이내 [NFR-PF-04]. 분석 1건 생성은 10분 이내 [NFR-PF-06].
- 원인 요약은 인과를 단정하지 않는다 — "때문에"가 아니라 "같은 시점에 ~가 있었다" [FR-CA-08].
- 매수 · 매도 의견을 생성하지 않는다 [FR-CA-09].
- 변동은 항상 변동률과 금액을 함께 제시한다.
- 같은 종목 · 날짜의 분석은 한 번만 생성하고, 동시에 생성되지 않도록 막는다 [FR-CA-10, FR-CA-11, NFR-RL-01].
- 같은 이벤트에 대한 중복 알림은 0건이어야 한다 [NFR-RL-02].
- LLM 한도 · 사용량 · 비용은 사용자 화면에 표시하지 않는다 [FR-AI-10].

## 5. 미해결 이슈

- OpenAI 응답에 인과 단정이나 매매 권유 표현이 섞여 나왔을 때 이를 검출하고 처리하는 방식이 정해지지 않았다.
- 네이버 뉴스를 종목명으로 검색할 때 동명 기업 · 무관 기사를 걸러내는 기준(관련도 판정)이 정해지지 않았다.
- 거래정지 · 상장폐지 등으로 당일 시세가 없는 종목의 처리 방식이 정해지지 않았다.
- 원문 링크가 삭제 · 만료되었을 때 저장된 제목 · 발췌로 대체할지 정해지지 않았다.
